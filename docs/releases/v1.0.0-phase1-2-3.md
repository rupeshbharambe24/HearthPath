## Phase 1 — Security & data integrity hardening (PR #1, merged)

Authoritative checks moved from client-side TypeScript to the database. Closes the 7 critical and 8 high audit findings.

- **users SELECT lockdown** — replaced `USING (true)` with self/partner policies + `discovery_candidates()` SECURITY DEFINER RPC
- **profile-photos bucket private** — `viewer_can_see_photo_level()` RPC + `signed-photo-url` edge fn
- **Permission stage triggers** — `permission_stage_requirements` table + INSERT/UPDATE triggers; only granter can revoke
- **Stage-request integrity trigger** — no forging, no skipping, no self-acceptance, idempotent
- **Server-side rate limits** — invites (3/day), reports (5/day, 24h dedup)
- **Block enforcement** — DB triggers on messages INSERT, relationships INSERT, message SELECT
- **Verification doc upload edge fn** — MIME allowlist + magic-byte sniff + 5MB cap
- **Account deletion purge** — `purge_user(uuid)` cascades across 13 tables (incl. fun_posts)
- **Admin gate moved to `admin_users` table** — VITE_ env var no longer in client bundle
- **Length CHECK constraints + Zod schemas** at form boundaries

**Migrations:** 11 new files (timestamps `20260425*`).
**Edge functions added:** `signed-photo-url`, `upload-verification-doc`. Modified: `delete-account`, `review-student-verifications`.

## Phase 2 — Features now real (PRs #2–#8)

Every audit-flagged stub now has a real implementation.

### #2 — Notifications inbox + read receipts + typing + presence (merged)
- `notifications` table populated by triggers on existing events (12 kinds: stage_requested/accepted/declined/deferred, permission_granted/revoked, heart_received, message_received, invitation_received/accepted/declined, breakup_initiated)
- `useNotifications` hook + `NotificationBell` + `NotificationInbox` UI
- `messages.read_at` column with receiver-only RLS UPDATE
- `ChatBubble` shows Check / CheckCheck for sent / read
- Typing indicators via Supabase Realtime broadcast
- Online presence via Supabase Realtime presence
- Block-aware: notifications suppressed when either party has blocked the other

### #3 — Real LLM AI summaries (merged)
- Provider abstraction (`_shared/llm/{types,provider,groq,selector,prompts}.ts`)
- Default: Groq Llama 3.3 70B Versatile via `LLM_PROVIDER` env var
- `generate-ai-summary` edge fn: auth + permission + cache (SHA-256 input hash) + 10/day rate limit + LLM call + persist
- `useGenerateSummary` hook + `AITransparencyPanel` consent UX
- System prompt enforces "neutral summary, never advice or diagnosis"
- Template fallback in `relationship-ai.ts` retained for offline / dev / LLM-down

### #4 — Memory attachments (merged)
- `memory-attachments` private bucket with path-based member-SELECT
- `upload-memory-attachment` edge fn (image/audio/pdf, 10MB, magic bytes)
- `signed-memory-attachment-url` edge fn re-checks visibility per request
- `MemoryAttachment` renderer (image / `<audio controls>` / pdf link)
- File picker integrated in MemoryTrail composer

### #5 — In-app moderation UI (open)
- Admin-bypass RLS on `reports` and `moderation_actions` (gated by `is_admin()`)
- `check_report_admin_update` trigger restricts mutations to `status` only
- `set_user_access_state(uuid, text)` RPC for admin-only suspend/reinstate
- `useAdminReports` hook family (list, detail, status, action, set-access)
- `/admin/moderation` page: filterable status list + detail with action footer (mark reviewing, add note, warn, restrict, suspend, reinstate, resolve, dismiss)
- Sidebar link gated on `useIsAdmin()`

### #6 — Onboarding autosave (open)
- `useOnboardingAutosave` hook: per-field UPDATE with column whitelist (21 writable fields), 600ms debounce, immediate save for selects/arrays, flush-on-blur
- `AutosaveStatus` indicator: "Saving…" / "Saved Xs ago" / "Save failed"
- All 21 onboarding fields wired (text inputs, year select, mode selects, chip toggles, custom-add chips, heartpath-norms checkbox)
- Continue handler flushes pending debounce before bulk save

### #7 — Voice notes (open)
- `voice-messages` private bucket with sender path-prefix + receiver-via-messages SELECT policy
- `upload-voice-message` edge fn: stage ≥ 3 check + receiver-granted permission check + MIME/size validation + atomic upload+insert
- `signed-voice-message-url` edge fn (5-min URL after RLS check)
- `useSignedVoiceMessage` hook
- `VoiceRecorder` component: MediaRecorder API, idle/recording/preview state machine, 60-second cap with countdown
- ChatRoom mic button gated on stage + permission; ChatBubble renders voice messages as `<audio controls>`

### #8 — Photo verification (DIY hybrid) (open)
- `photo-verifications` private bucket with self-read policy
- `upload-photo-verification` edge fn (jpeg/png/webp, 5MB, magic bytes)
- `review-photo-verifications` admin edge fn — signs both selfie + ID for side-by-side review
- `SelfieCapture` component (webcam → snapshot → preview)
- Profile entry point: "Verify your photo" Dialog
- AdminVerifications page extended with "Photo verification" tab
- On admin approve: `verification_badges.photo_verified = true`

## Recommended merge order

The 7 open PRs touch disjoint surfaces (verified by reviewer agents per PR). Merge in any order; below is the suggested sequence to minimize cognitive load and ensure each merge can be smoke-tested before the next:

```
1. PR #5 — moderation-ui          (admin tooling — independent)
2. PR #6 — onboarding-autosave    (frontend only — zero infra)
3. PR #9 — stage-celebration      (frontend only — zero infra; preferred next because it's the most visible)
4. PR #10 — settings-lifecycle    (DB migration + 1 edge fn)
5. PR #7 — voice-notes            (DB migration + 2 edge fns)
6. PR #8 — photo-verification     (DB migration + 2 edge fns)
7. PR #11 — memory-i18n-pwa-a11y  (frontend only — zero infra; PWA changes vite.config so do it last)
```

After each merge, run on your authenticated CLI:

```bash
git checkout main && git pull
supabase db push   # only when migrations exist; idempotent
supabase functions deploy <new-functions-from-the-PR>
```
